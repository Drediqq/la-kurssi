How the script works

The script collects server information using Linux commands and stores the results in Bash variables through command substitution. A function uses an if statement to determine the disk space status. Script writes values for each server statistic to different files, which when are read by javascript script and then stats are dynamically updated to the table in html. Most of the bash script is rather simple, most of the values are preparsed to look like I want them to look like. Only more "complex" part is diskusage which is changed to "warning" or "ok" based on value that is returned by df -h / | awk 'NR==2 {print $5}' | tr -d '%' command.

How do the stats update

The script writes separate files for each statistic and then overwrites them with new information every minute. Javascript handles the refresh of statistics without reloading the whole page, becouse that would be rather annoying. Nginx serves this pseudodynamic file at (ip)/week3/.

Why does the script write multiple files?

Becouse it's very easy to use those files when theres exactly one thing in them it also makes debugging easy.

Disk space function

Disk usage part of the script is a very simple if else structure, which gets the percentage of used disk space then stripped value is compared to 95 and 80 which determines the output. when value is 80, script writes "WARNING" to a file which is then shown in the table.

Piping example

First we get specifically root disks(/) (-h)uman readable statistics df -h /

which for example returns something like this:

Filesystem      Size  Used Avail Use% Mounted on
/dev/nvme0n1p2   98G   22G   72G  24% /

So I only care about use% statistic, therefore I'll pipe it to awk

df -h / | awk 'NR==2 {print $5}'

which then returns:

24%

This is great and all, but nobody likes % values in their simple math, so I'll pipe it to tr

df -h / | awk 'NR==2 {print $5}' | tr -d '%'

which then returns:

24

Now its easy to do some math!

Scheduling

I used cron instead of sysd timer, both are rather easy to replicate, but i find crons to be a bit easier and more appropriate for just running a single bash script in very short timer. As long as cron is enabled as sysd service, crons will run when specified.

This is the current cron setup, It runs every minute of every hour of every day of every week of every year forever:

* * * * * location/of/script.sh >/dev/null 2>&1

dev/null 2>&1 stops it to not spam logfiles full of poop

*/5 * * * * location/of/script.sh
This would run every 5 minutes
0 * * * * location/of/script.sh
This would run every hour
0 0 * * * location/of/script.sh
This would run at 00:00 every day
37 13 6 9 * location/of/script.sh
This would run at 13:37 on 6. September every year
